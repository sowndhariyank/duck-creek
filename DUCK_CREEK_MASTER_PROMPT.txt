# MISSION

Develop a **Production-Ready Agentic Solution** for insurance underwriting, taken **from concept to production** using **Google's AI Black Belt methodology**. It acts as a **trusted advisor** that **assists underwriters** and **increases operational efficiency**.

Build it as a **new multi-agent system** using **Google ADK 2.x** and **A2UI**, composed of **multiple subagents** derived from both the **generally accepted underwriting workflow** and the requirements below.

# REQUIREMENTS

## R1 — Production-Ready Agentic Solution
Production-ready, not a prototype. Concept to production. Follows the AI Black Belt methodology with explicit phase gates. Acts as a trusted advisor, assists underwriters, increases operational efficiency.

## R2 — Accuracy and Explainability
Build an **"explainable AI workbench"** that gives **brokers clear insights** and **justifies rating scores based on specific risk factors**. Prioritize **accuracy** and **reliability**; **minimize hallucinations** — these are **critical risk decisions**.

Implement **deterministic, auditable, and traceable** AI models, referred to as **"neuro-symbolic deterministic AI"**: a neural layer (LLM/embeddings) for extraction, retrieval, classification and natural-language explanation, bound to a symbolic layer (explicit versioned rules) that owns every score, rate, and decision. Same inputs + same rule version ⇒ identical output and identical decision trace. Ensure **transparency** and **satisfy regulatory requirements**.

## R3 — Streamline Underwriting Workflows
**Data enrichment**, **holistic risk summarization**, and **generating multiple quotes** — all **without manual re-entry**. Manage the **entire quote lifecycle** so no quote becomes **fragmented** or **orphaned**. Support **autonomous processing for low-risk quotes**, with a **human-in-the-loop workflow for out-of-bounds or mediocre-risk cases**.

## R4 — Operational Efficiency
**Automate manual risk decision workflows**: data enrichment, risk summarization, and generating multiple quote options.

## R5 — Accuracy (hard constraint)
Highly accurate and reliable. **Strict requirement: the AI must not hallucinate**, given its critical role in risk assessment. Enforce this mechanically, not aspirationally — every factual claim in generated output must carry a resolvable citation to a document span, an enrichment response, or a rule ID. Uncited claims are blocked, not warned about.

# REQUIRED APIs & SERVICES

Use every one of these, for the stated purpose:

| Service | Purpose |
|---|---|
| **Google Cloud Storage API** | Upload policy documents and relevant files into a cloud storage bucket |
| **Document AI (Doc AI) API** | Ingest unstructured data for embeddings and minimize hallucination rates |
| **BigQuery API** | Bring unstructured data into BigQuery for embeddings |
| **Apigee API** | API orchestration to enable modular agent integration |
| **Looker API** | Support creating a semantic layer and performance dashboards |
| **Agent Gateway API** | Envoy-based egress/ingress proxying for securing tool-level authorization |
| **Agent Identity API** | SPIFFE-based token down-scoping for securing tool-level authorization |
| **Google Kubernetes Engine (GKE) API** | Container deployment alongside Cloud Run |
| **Cloud Run API** | Deploy agent functions into a serverless environment |

**Dependency note:** For Apigee and Looker, **Scott Hitchcock is requesting trial environments**. Treat both as pending-access dependencies — design behind an interface, stub locally so nothing is blocked, and track them as a named delivery risk.

# SUBAGENTS

Derive the subagent set from the generally accepted underwriting workflow — submission intake, clearance, appetite/eligibility, data enrichment, exposure analysis, loss history, risk scoring and rating, quote generation, compliance check, referral vs. straight-through decision, quote lifecycle management, and audit — and extend it as the requirements above demand.

Propose the roster in your spec and justify each agent. Two constraints on the design:
- The rating/scoring agent is the symbolic layer: deterministic, versioned, **zero LLM calls**. No model may produce a rate, premium, score, or bind/decline decision.
- Every other agent's output is grounded and cited, or it is blocked.

# DONE MEANS

- A document uploaded to Cloud Storage flows end to end into multiple priced quote options with zero re-keying.
- Every number traces to a rule ID and a cited input; reruns produce identical decision traces.
- The workbench shows factor-by-factor score justification with evidence drill-down, legible to a broker.
- Low-risk goes straight through; out-of-bounds and mediocre-risk land in a referral queue with a brief.
- No quote can end up fragmented or orphaned.
- Every tool call is authorized through Agent Gateway with a down-scoped SPIFFE identity.
- A regulator-ready audit pack can be exported for any decision.
- Groundedness evals gate CI at zero uncited claims.
- All nine services provisioned in Terraform; agent functions on Cloud Run, containers on GKE alongside.
