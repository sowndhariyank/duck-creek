1. GEMINI.md — THE SECURITY, COMPLIANCE & ENGINEERING RULEBOOK
========================================================================================

A. WHY DID WE USE THIS FILE?
Insurance underwriting involves sensitive commercial policy data and strict state 
insurance regulatory compliance. We cannot allow an AI system to use unapproved consumer 
APIs, insecure API keys, or untested "black-box" code. GEMINI.md acts as the Mandatory 
Development Rulebook governing how the AI assistant writes code, accesses Google Cloud, 
and enforces zero-trust security.

B. HOW IS IT HELPFUL TO DUCK CREEK?
1. Guarantees Enterprise Data Privacy: Mandates Google Cloud Vertex AI Enterprise 
   connectivity (GOOGLE_GENAI_USE_VERTEXAI=true), ensuring customer policy data is never 
   logged, leaked, or used to train public models.
2. Eliminates Code Bugs with TDD: Enforces Test-Driven Development (TDD) — no code is 
   deployed without automated unit and integration tests (pytest).
3. Consistent Production Standards: Mandates strict static typing (mypy) and PEP-8 
   linting across all Python files.

C. DETAILED SECTION-BY-SECTION BREAKDOWN:
- "Role & Identity": Defines the AI assistant as an expert software engineer specializing 
  in Google Cloud's Agent Development Kit (ADK) and A2UI (Agent UI). Ensures the AI acts 
  as an enterprise insurance architect rather than a general-purpose chatbot.
- "Tech Stack": Establishes the exact, approved enterprise technologies (ADK 2.x, A2UI, 
  Vertex AI Enterprise google-genai, pytest, mypy) so everything integrates seamlessly.
- "The 4 Vibe Coding Principles": Modern software engineering rules:
  1. Natural Language is Source of Truth: Prompts define business intent.
  2. Run > Read (TDD as the Vibe Check): Verify locally with tests before trusting code.
  3. Iterative and Incremental: Build modular components instead of monolithic mega-files.
  4. Error-Driven Development: Fix root causes immediately using full stack traces.
- "Mandatory Development Guidelines & Security": Strict security boundary. NEVER use 
  consumer GOOGLE_API_KEY or legacy google.generativeai. ALWAYS initialize the client 
  with enterprise=True on Vertex AI (project: arsanjani-genai, location: us-central1).
- "Operational Guidelines": Requires .venv virtual environments, git tracking, and 
  referencing architecture specs before writing code.

2. architecture.md — THE MASTER MULTI-AGENT ARCHITECTURE BLUEPRINT
========================================================================================

A. WHY DID WE USE THIS FILE?
Commercial property underwriting is too complex for a single AI agent. It involves document 
ingestion, OFAC sanction checks, NAICS industry classification, geospatial flood/wildfire 
queries, building structural evaluation (COPE), 5-year claims triangles, and deterministic 
rating math. architecture.md defines the Hub-and-Spoke multi-agent system structure and how 
all 9 Google Cloud Services work together.

B. HOW IS IT HELPFUL TO DUCK CREEK?
1. Clean Modular Microservices: Duck Creek can plug in existing core systems (like Duck 
   Creek Policy, Billing, or Claims) into dedicated worker agents without rewriting the 
   entire platform.
2. Neuro-Symbolic Rating Separation: Guarantees that AI models are used only for text reading 
   and summarization, while 100% of insurance pricing and rating is done by pure mathematical 
   formulas (Zero-LLM Actuary).
3. Clear Infrastructure as Code (IaC): Maps directly to Terraform scripts for rapid deployment 
   on Google Cloud.

C. DETAILED SECTION-BY-SECTION BREAKDOWN:
- "Multi-Agent Hub-and-Spoke Topology": A central Lead Underwriting Orchestrator coordinating 
  12 specialized worker agents (Intake Doc AI, OFAC Clearance, Appetite NAICS, Apigee Hazard, 
  COPE Exposure, Loss History, Symbolic Actuary, Quote Structuring, Grounding Guard, Triage 
  STP, Quote Lifecycle, and Audit Governance).
- "The 9 Enterprise Google Cloud Services":
  1. Cloud Storage (GCS): Stores raw broker PDFs (ACORD 125, ACORD 140, SOVs).
  2. Document AI API: Reads scanned text and saves exact page & character coordinates.
  3. BigQuery API: Immutable event ledger storing quote states and audit trails.
  4. Apigee API Gateway: Secure API connector to external data providers (FEMA, ISO PPC).
  5. Looker API: Underwriting loss ratio dashboards and portfolio analytics.
  6. Agent Gateway API (Envoy): Security proxy that monitors and authorizes every agent tool call.
  7. Agent Identity API (SPIFFE): Assigns restricted digital ID badges to each subagent.
  8. GKE & Cloud Run: Scalable serverless compute infrastructure.
- "Neuro-Symbolic Actuarial Partitioning": The mathematical formula for commercial property 
  rating: Premium = (TIV / 100) * BaseRate * F_territory * F_construction * F_protection * E_mod. 
  Proves that every dollar of insurance premium is calculated by mathematical formulas 
  referencing state-filed ISO rules with zero generative AI tokens used.

3. orchestration.md — THE CONDUCTOR'S SCORE (FRACTAL CHAIN OF THOUGHT)
========================================================================================

A. WHY DID WE USE THIS FILE?
Without explicit orchestration rules, multi-agent AI systems often generate superficial 
summaries, skip important validation steps, or exit prematurely. orchestration.md provides 
the exact prompt template and reasoning engine (Fractal Chain of Thought / FCoT) that the 
Lead Orchestrator uses to direct all 12 worker agents.

B. HOW IS IT HELPFUL TO DUCK CREEK?
1. Multi-Scale Risk Analysis: Analyzes insurance risk across 3 distinct perspectives:
   - Macro: Industry appetite (NAICS 541512), portfolio limits, and OFAC sanctions.
   - Meso: Regional hazard exposure (FEMA flood zones, wildfire indices, fire station distance).
   - Micro: Line-item asset values ($12.5M TIV), character-level citations, and 5-year claims.
2. Prevents Agent Bottlenecks: Uses silent internal transfers (transfer_to_agent) to run all 
   13 subagents sequentially in under 15 seconds without user intervention.
3. Real-Time Streaming to A2UI: Transforms agent thoughts and completed turns into live 
   Server-Sent Events (SSE) displayed on the Underwriter Workbench.

C. DETAILED SECTION-BY-SECTION BREAKDOWN:
- "Role & System Definition": Establishes the Lead Orchestrator as the master underwriting 
  supervisor responsible for sequential agent dispatch, evidence verification, and UI schema.
- "The 4 Operational Invariants":
  1. Sequential Silent Dispatch: Dispatches subagents one by one without stopping early.
  2. Epistemic Citation Provenance: Mandates that every extracted fact must carry a link to 
     a document page or API receipt.
  3. Neuro-Symbolic Separation: Neural models handle text; pure Python handles numbers.
  4. Dynamic A2UI Schema Generation: Compiles the final findings into interactive UI cards.
- "FCoT Analytical Phases (1 through 5)": Step-by-step instructions for Phase 1 (Intake & 
  Clearance), Phase 2 (Hazard & COPE Enrichment), Phase 3 (Symbolic Pricing & Quotes), 
  Phase 4 (AST Grounding & STP Triage), and Phase 5 (State Machine & Audit Pack).

4. sequential_multi_agent_development_guide.md — THE ANTI-CHAOS & COMMUNICATION PROTOCOL
========================================================================================

A. WHY DID WE USE THIS FILE?
When multiple AI agents collaborate, they can easily cause chaos if they try to command 
one another, create circular messaging loops, or step on each other's memory. This guide 
establishes the Multi-Agent Traffic Rules (Communication Protocol) to ensure clean, isolated, 
and deadlock-free execution.

B. HOW IS IT HELPFUL TO DUCK CREEK?
1. Zero Agent Deadlocks: Workers never communicate directly with each other (peer-to-peer); 
   they only report back to the Lead Orchestrator. This eliminates infinite loops and race conditions.
2. Least-Privilege Security Isolation: An intake agent that reads documents cannot accidentally 
   trigger policy binding or modify database records.
3. Complete Explainability & Auditability: Because each subagent receives a clean JSON input 
   and emits a clean JSON output, every step can be inspected in the Agent Mesh Dossier and 
   exported for state insurance regulators.

C. DETAILED SECTION-BY-SECTION BREAKDOWN:
- "Multi-Agent Topology Patterns": Explains why a centralized supervisor coordinating isolated 
  specialists (Hub-and-Spoke) is the safest and most scalable design for enterprise insurance.
- "State Machine Progression & Memory Isolation": Rules for how data passes between agents via 
  structured Pydantic records (SubmissionProfile, HazardEnrichmentResult, RatingTraceRecord) 
  rather than raw unstructured chat text.
- "Error Handling & Graceful Degradation": Fallback mechanisms when an external API (like a 
  flood map lookup) is temporarily unavailable, ensuring the system flags missing data for an 
  underwriter rather than crashing.
